Debugging

Going through a program

  • F7 (Step) runs one instruction. The next instruction is highlighted in the Text Segment, and the registers and memory it changed are highlighted too.
  • F8 (Backstep) undoes the last step, up to 2,000 steps back. A run at full speed keeps no history unless Settings > Enable Backstep While Running is on.
  • A tick in the Bkpt column of the Text Segment sets a breakpoint: Go stops before that instruction. Ctrl+K clears all the breakpoints, Ctrl+T turns them off and on.
  • The Run speed slider runs 1 to 30 instructions a second, showing each one. At its right end the program runs at full speed.
  • F9 (Pause) and F11 (Stop) halt a running program.
  • F12 (Reset) loads the program again, with the registers and memory as at its start.

Looking at memory

The Data Segment shows 128 words at a time. Its Previous and Next buttons go to the page before and after; Hexadecimal Addresses, Hexadecimal Values and ASCII change how it shows them.

Below the Data Segment, a list jumps to a place: .data (the start of the program's data), current SP (the page of the stack pointer), .text (the program's code) and JTAG UART. While no program is assembled the Data Segment is empty and the list is gray, reading ".data: no program assembled". While SP has its start value 0, the current SP entry reads "current SP: stack at 0xfffffffc" and shows the last page of the on-chip memory, where the first PUSH stores.

With Settings > Show Labels Window on, a double-click on a label shows its address in the Text Segment or the Data Segment. While no program is running, the values of the registers can be changed by hand: the Registers tab under ARM tells how.

How a program ends

  • SVC #10 or SVC #17, and a branch to itself (B .), end it with -- program is finished running --.
  • Running past the last instruction ends it with -- program is finished running (dropped off bottom) --.
  • An error, such as an access to an address with no memory, stops it with a runtime error in ARES Messages and Run I/O, and the instruction turns light red. The registers and memory stay as they were, to see what happened; Reset starts the program again. Backstep still works, to see what led to the error, as far as it has history.
