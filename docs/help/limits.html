ARES - ARM Educational Simulator

Release 1.0

November 2026

Limitations

ARES is made for learning, and simulates what a program needs to run. This is what it does not do.

The computer

  • ARES is made for ARM state. Thumb code is not supported: it can run for a while, but SVC does not work in it, and BLX label to Thumb code at the end of the program leaves the program.
  • There are no interrupts and no timers. Nothing is ever taken as an exception: SVC goes to ARES's own services, and an undefined instruction or an access to an address with no memory ends the program with a runtime error, with no exception vector and no handler.
  • There is no memory management unit and no cache: the Data Cache Simulator is a model that counts.
  • ARES counts instructions, not time: there are no cycles.
  • The Cortex-A9 has no divide instruction: use a loop, or floating point.
  • Only these coprocessor instructions work: those of the floating-point unit, coprocessors 10 and 11, and MRC and MCR on a register of 14, the debug unit, or 15, the system's, that can be read or written that way. Any other, such as CDP or MRRC on 14 or 15, is an undefined instruction: unless its condition fails, it ends the program with a runtime error.
  • The only device without a tool is the JTAG UART. The other DE1-SoC devices ignore writes and read as 0, and ARES Messages warns once for each address that a program uses; the Digital Lab Sim brings the red LEDs, the seven-segment displays, the switches and the push buttons to life.
  • Memory is what the Memory and devices tab lists: 1 GB of DDR3 and 64 KB of on-chip memory.

The program and the window

  • A program is one file: Assemble takes the file on top and links nothing else with it.
  • Backstep goes back at most 2,000 steps.
  • System calls 31 and 33 play no sound.
  • The numbers of the system calls are those of the Syscalls tab; any other number ends the program with a runtime error.

The tools

  • A connected tool can make a run at full speed take longer, as its page says.
  • BHT Simulator: only conditional branches are predicted, not B without a condition, BL, BX or other instructions that change PC.
  • Digital Lab Sim: the program cannot write the switches, and the interrupt mask is only stored.
  • Dynamic Instruction Counter: it counts instructions and has no cycles.
  • Keyboard and Display MMIO Simulator: text printed by system calls shows only in Run I/O.
  • Memory Reference Visualization: memory that a system call reads or writes for the program does not count.

Forms the lists do not show

  • CMPP, CMNP, TSTP, TEQP: old forms of the comparisons for User mode's flags.
  • VADDQ.I32 and the like: Neon names with Q added: the Q registers already say it.
  • ADDUL and the like: UL is another way to write the condition LO.
  • CMPS, CMNS, TSTS, TEQS: S on a comparison is out of date: a comparison always sets the flags.
  • MOVEQ R1, #0x1234 and the like: the conditions of the alias are those of MOVW, on the Basic list.
  • LDRBEQ, LDMIAEQ and the like: the assembler wants the condition before the ending, LDREQB and LDMEQIA, unless the program has .syntax unified.
